Boot Flow Lifecycle

七大開機執行階段生命週期

從 Reset Vector 唯讀韌體代碼逐步建立信任根，平滑交接至作業系統核心

PHASE 1
SEC
重設向量、建立 Cache-as-RAM (CAR)、平台信任根驗證
PHASE 2
PEI
PEIM 模組初始化 DRAM 與晶片組，產出 HOB 清單
PHASE 3
DXE
核心執行環境，初始化 System Table 並載入各硬體驅動
PHASE 4
BDS
Boot Manager 解析 Boot#### 與 BootOrder，啟動開機選項
PHASE 5
TSL
OS Loader 接管控制權，呼叫 Boot Services 載入核心
PHASE 6
RT
ExitBootServices() 釋放記憶體，僅保留 Runtime Services
PHASE 7
AL
系統崩潰或重啟時由韌體進行災難復原

關鍵交接邊界 (Boundary)：在 TSL 邁入 RT 階段時，OS Loader 必須觸發 ExitBootServices()。此時所有開機服務記憶體被釋放並交給作業系統核心管理，標誌著平台韌體從「控制主導」轉為「輔助執行」。

Core Architecture

EFI 系統表結構 (EFI System Table)

所有 UEFI 應用程式與驅動程式存取韌體與硬體能力的標準核心分發入口

📦 Boot Services Table

僅在 ExitBootServices() 前有效

  • 記憶體管理：AllocatePages, GetMemoryMap
  • 非同步事件：CreateEvent, SetTimer, TPL 優先級
  • 物件控制代碼：Handle & Protocol 資料庫
  • 映像生命週期：LoadImage, StartImage

⚡ Runtime Services Table

OS 運行期間全程常駐記憶體

  • 變數服務：GetVariable, SetVariable (NVRAM)
  • 時間服務：GetTime, SetWakeupTime (RTC)
  • 膠囊更新：UpdateCapsule (韌體帶內升級)
  • 虛擬位址重對映：SetVirtualAddressMap

📑 Configuration Tables

標準硬體描述資料表介面

  • ACPI Tables：RSDP, DSDT, SSDT 電源與硬體配置表
  • SMBIOS Tables：提供主機板、BIOS、記憶體規格資訊
  • Device Tree / Device Paths：嵌入式與非 x86 硬體描述
Extensibility & Modularity

物件導向協議與驅動程式模型

基於 COM 概念之 Handle-Protocol 資料庫，達成高內聚、低耦合硬體抽象

🧩 Handle 與 Protocol 架構

  • Handle (控制代碼)：代表系統中抽象的實體控制器或邏輯設備（如 PCI 總線、硬碟分區）。
  • Protocol (協議介面)：一組由 128-bit GUID 唯一識別的函式指標結構體（如 BlockIoProtocol, GraphicsOutputProtocol）。
  • Handle Database：動態關聯各 Handle 與其掛載的多個 Protocols，支援動態擴展與查詢。

⚙️ UEFI Driver Binding Protocol

標準驅動程式透過三個核心函式生命週期驅動設備：

Supported() 測試驅動是否支援目標設備 Handle
Start() 綁定控制器並產生子 Handle 或子 Protocol
Stop() 釋放資源並安全卸載驅動程式
Storage Architecture

GUID Partition Table (GPT) 磁碟分區

規範第 5 章標準，徹底打破傳統 MBR 限制並引入雙向冗餘災難校驗

🛡️ Protective MBR (LBA 0)

在磁碟第 0 扇區保留保護性 MBR，標記整個磁碟為 0xEE 類型。防止不支援 GPT 的老舊磁碟分割工具誤將磁碟視為未格式化而覆寫資料。

📑 Primary GPT (LBA 1 ~ 33)

  • GPT Header (LBA 1)：記錄 Unique Disk GUID、分區表大小與自身 CRC32 校驗和。
  • Partition Entries (LBA 2~33)：定義最多 128 個分區項，每項具備 Type GUID 與 Unique GUID。

🔄 Backup GPT (磁碟末端)

在磁碟最後的 33 個 LBA 保留鏡像備份（Secondary GPT Header 與 Entries）。當主分區表損壞時，韌體自動偵測並依賴備份無縫復原。

📊 GPT vs. MBR 核心對比

• 最大磁碟容量：MBR 僅支援 2.2 TB (32-bit LBA) ➔ GPT 支援高達 9.4 ZB (64-bit LBA)
• 主分區數量：MBR 限制 4 個主分區 ➔ GPT 預設支援 128 個獨立分區
• 完整性校驗：MBR 無校驗機制 ➔ GPT 具備 Header 與 Partition Table 雙重 CRC32 校驗

Firmware Security

Secure Boot 與韌體信任鏈機制

基於非對稱加密金鑰階層，確保開機載入的每一個映像檔均具備數位簽章認證

🔑 四層金鑰管理階層

PK (Platform Key)
代表 OEM/主機板製造商，信任根頂點
Root of Trust
KEK (Key Exchange Key)
用於簽署與授權更新 db / dbx 安全資料庫
Exchange Key
db (Authorized Database)
白名單：受信任之 X.509 憑證或二進位 SHA-256
Whitelist
dbx (Forbidden Database)
黑名單：優先權最高，符合者立即拒絕載入
Blacklist

🐧 Linux 生態：Shim 與 MOK 機制

  • 微軟 3rd Party CA 簽名：全球 PC 預載微軟憑證，因此開源社群由微軟統一為 shimx64.efi 提供簽名。
  • Shim 載入器：作為第一階 Loader 驗證發行版簽章與 GRUB。
  • MOK (Machine Owner Key)：提供實體操作介面，允許使用者自行登記信任自編核心與驅動。
  • TPM 2.0 測量開機 (Measured Boot)：代碼執行前擴展至 TPM PCR 暫存器，提供遠端證明與 BitLocker 解密封印。

Summary & Outlook

技術權衡與韌體架構展望

在高度擴展靈活性與系統安全性、開機效率之間的工程平衡

⚖️ 當前挑戰與爭議

  • 龐大代碼量與攻擊面：數百萬行 C 語言代碼帶來 Bootkit（如 BlackLotus）高價值攻擊目標。
  • 閉源生態審查壁壘：儘管 EDK II 開源，實際出貨仍高度依賴少數 IBV（AMI, Insyde）二進位模組。
  • NVRAM 儲存危機：黑名單 dbx 快速膨脹，考驗老舊主機板 SPI Flash 容限。

🔮 未來韌體演進趨勢

  • LinuxBoot / coreboot 興起：超大規模資料中心（Hyperscalers）逐漸採用 Linux Kernel 作為 Payload，開機時間從分鐘級縮短至秒級。
  • Rust 語言進入韌體層：以記憶體安全語言重寫 PEI/DXE 核心模組，從根本杜絕記憶體損毀漏洞。
  • 端到端遙測與遠端證明：配合 TPM 與 Confidential Computing 達成全週期零信任開機。
